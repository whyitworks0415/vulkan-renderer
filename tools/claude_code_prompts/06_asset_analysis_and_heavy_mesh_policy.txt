Task: add tooling and policy for identifying assets that are too heavy for this renderer's current architecture.

Context:
- `EinsteinBustTongue.stl` is extremely heavy relative to the rest of the project.
- Current project has no built-in report that tells us which assets dominate load time, triangle count, or memory footprint.
- Even after code improvements, oversized assets will still cause pain without visibility.
- Relevant files:
  - tools/ (preferred location for scripts or reports)
  - optionally src/ if a tiny runtime warning hook is justified

Goal:
- Make asset risk visible and actionable.

Requested changes:
1. Add a small local analysis tool or script under `tools/` that scans known asset files and reports:
   - file size
   - estimated triangle count when practical
   - approximate vertex/index memory cost under the current loader strategy
2. Generate a human-readable report file in the repo that summarizes the current assets and flags suspiciously heavy meshes.
3. Add simple thresholds or warnings in the report, for example "high risk for scene-switch hitch" or "requires LOD/proxy."
4. If appropriate, add a lightweight runtime warning when a loaded mesh crosses a very large triangle threshold, but keep it non-fatal.

Constraints:
- Do not download third-party tools.
- Keep the tool simple and maintainable.
- Do not attempt full mesh decimation in this part.

Definition of done:
- There is a usable local tool under `tools/`.
- There is a report file in the repo summarizing current asset risk.
- The report clearly identifies heavy assets such as `EinsteinBustTongue.stl`.

Please include in your final response:
- files changed
- how to run the tool
- summary of the heaviest assets it found
